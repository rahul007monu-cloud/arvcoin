# USD dual-price display, ₹10k anchor retarget with candle rebuild, and CoinDCX-style mobile nav (v1)

Three changes ride together on `fix-arv-usd-display-and-price-spike`. The anchor retarget moves `arv_base_inr` 1.78 → 17.83 (and the matching `_schema.php` defaults + `_money.php`/`market.php` fallbacks), bumps `ARV_SCHEMA_VERSION` 8 → 9, and adds a guarded schema-9 migration that force-sets the four anchor settings and re-queues an *unconditional* full ARV candle rebuild via a new `arv_candles_rebuild_v9` flag that `auto_backfill_step()` honours by bypassing the row-count skip. The USD work adds `setUsdInr`/`fmtUsd`/`fmtDual`/`paintPriceDual` to `js/ui.js` and threads a live-only `$` companion onto every live-price surface while leaving historical/point-in-time figures ₹-only. Part C adds a mobile-only fixed bottom tab bar, a Help footer column, and a `mailto:info@ARVcoin.com` link. The money path (orders, ledger, lots, paise cost basis) is untouched by all three.

The anchor target of ~₹10,000 (base 17.83) follows the later user steering that superseded the original ₹1000 ask, so the retarget is judged against ₹10,000 here; note this contradicts `context.json`'s `user_decisions` field, which still records the ₹1000/1.78 decision — a stale artifact, not a code problem.

**Watch for:** the candle rebuild is overwrite-by-timestamp only (no `DELETE` of the old ARV range), so any old-anchor row at a timestamp the exchange no longer pages can survive the rebuild — **likely** the main residual spike risk (verify on the live install). The `arv_candles_rebuild_v9` flag is not cleared on the 20-fail "skip past this step" branch of `auto_backfill_step()` — **confirmed**, self-heals on the next step but worth tightening. Runtime (migration, backfill, ingest) is unverifiable in the sandbox; correctness below is by reading.

**Verdict**: NEEDS_CHANGES

## High-level view

The schema-9 migration writes only settings and backfill-scheduling flags — no wallet, lot, or ledger row is touched, and it does not re-run v8's unit rescale (the `units_rescaled_v8` guard is left alone), so there is no double-rescale path. Holding value is preserved because only the printed per-unit NAV/candles change, not unit counts.

The spike fix is correct in mechanism but incomplete in guarantee. Bypassing the row-count skip while the rebuild flag is set means every ARV timeframe is genuinely recomputed through `index_price()` against the single new anchor, which is what v8 failed to do. But `backfill_tf()` overwrites candles only at timestamps the current exchange fetch returns (`ON DUPLICATE KEY UPDATE` keyed on `(tf, ts)`), and nothing deletes the pre-existing old-anchor rows first. Deep 1D/1W frames re-page from launch and are effectively fully rewritten; the bounded sub-hour frames are not guaranteed to hit every old timestamp, so a stranded old-anchor row remains possible.

The flag lifecycle is sound on the normal skip and success paths — it clears the moment the chain advances into an asset step or `done` — but the catch block's 20-fail skip advances the chain without clearing the flag, relying on a later step to clear it.

The USD display is defensive: `fmtUsd` degrades to an em-dash on null/NaN NAV or a missing rate, so no `NaN`/`$Infinity` reaches the screen. Historical surfaces (avg cost, tax, transactions) are correctly left ₹-only. Two surfaces (dashboard wallet, portfolio ARV value) build the `$` companion inline rather than through `fmtDual`, so their em-dash fallback renders `(—)` instead of dropping the parenthetical.

The mobile tab bar is auth-gated correctly — signed-out users never see an account-only destination — sign-out is unaffected, and the mailto address is exactly `info@ARVcoin.com`. One display-only gap: the bottom bar appears at ≤760px but the top links collapse into the hamburger at ≤880px, leaving a 761–880px band with neither the inline links nor the bottom bar.

### Money-path isolation of the schema-9 migration

The migration block is guarded by `anchor_recomputed_v9` and runs its body exactly once: it `setting_set`s the four anchors, resets the backfill scheduler (`auto_backfill_next='1D'`, fails cleared), raises `arv_candles_rebuild_v9`, then sets its own guard. Every write is a settings write. There is no `UPDATE wallets`, no lot re-division, no ledger insert, and no reference to `units_rescaled_v8` — so v8's one-time unit rescale cannot fire again from here, and there is no double-rescale path. The invariant the fix leans on is holding value = units × NAV, and only NAV/candles (display) change, not unit counts. The anchor force-set is unconditional, unlike v8's "only if still on old defaults" guard — deliberate, since it must repair installs left in any partial state by v8 and settings carry no money.

### Candle rebuild: recompute is real, deletion is missing

```
auto_backfill_step():
  $rebuildArv = ($assetKey === null) && arv_candles_rebuild_v9
  if (!$rebuildArv && $have >= floor($tf)) { skip; maybe clear flag }
  else { backfill_tf($tf) -> recompute via index_price(new anchor) }
```

While the flag is set, ARV timeframes never take the skip, so each is re-run through `backfill_tf()`, which recomputes open/high/low/close via `index_price()` against the current anchor — the recompute v8 skipped. The chain is `1D→1W→1h→15m→5m→1m` then the first asset step, so a full sweep rebuilds every ARV frame and then clears the flag.

The gap: recompute writes with `ON DUPLICATE KEY UPDATE` keyed on `(tf, ts)` and nothing deletes the existing ARV rows first:

```php
'INSERT INTO arv_candles (tf, ts, ...) VALUES (...)
 ON DUPLICATE KEY UPDATE open=VALUES(open), ... close=VALUES(close), ...'
```

Only timestamps the current fetch returns get overwritten. For 1D/1W the window is from launch (`$days=0`), so the deep body is fully rewritten. For the sub-hour frames the window is bounded (1m=7d, 5m=30d, 15m=90d, 1h=90d), and there is no guarantee the exchange re-serves the identical timestamp set the old install stored. Any old-anchor row at a timestamp not re-paged survives — and a single surviving old-anchor row adjacent to new-anchor rows is precisely the discontinuity this change exists to remove. A `DELETE FROM arv_candles WHERE tf = ?` at the head of each rebuilt frame would make the rebuild total instead of best-effort. Confidence: **likely** for the sub-hour frames; **possible** that the exchanges re-serve every timestamp in practice and the point is moot — that is what to check on the live install.

### sinceLaunchPct consistency

`window_stats()` and `handle_snapshot()` both read `arv_base_inr` for the `(nav-base)/base` since-launch computation, and their fallbacks were moved to 17.83 to match `index_price()`. Base and candles must share one anchor or the percentage is nonsense — that mismatch produced the +34027% on the mixed-anchor series. This holds only to the extent the previous concern (no stranded old-anchor rows) holds; a surviving old-anchor row in the series still poisons the launch percentage.

### Rebuild flag lifecycle

The catch block's 20-fail branch is the hole: it sets `auto_backfill_next = auto_backfill_after($next)` to skip an unpageable step but does not clear `arv_candles_rebuild_v9`. If the skipped step is the last ARV frame (`1m`), the chain lands on the first asset step with the flag still raised; on the next tick `$rebuildArv` is false for asset steps, and the normal skip/backfill path clears the flag when it advances. So it self-heals within one extra tick and never loops forever (asset steps can't set `$rebuildArv`). Adding the same clear-on-advance guard to the 20-fail branch makes the "one-pass corrective" claim literally true. Confidence: **confirmed** (the branch has no clear), impact minor.

### USD companion: fallback behaviour and where it is / isn't applied

`fmtUsd` returns the em-dash when rupees is null/NaN, when the rate is missing, or when the quotient is non-finite, so `NaN`/`$Infinity` cannot render; `usdInr()` falls back to `CFG.FEED.fx.fallbackRate` (94.95), validated `> 0` and finite, and `setUsdInr` ignores non-positive/non-finite input. Live surfaces (nav ticker, hero, ATH/ATL, watchlist ARV row, trade price/high/low, admin price + obligation) go through `fmtDual`/`paintPriceDual`; historical surfaces (avg cost, tax, transactions) stay ₹-only — the intended split, since a point-in-time cost basis converted at today's rate would mislead.

Two spots — dashboard wallet value and portfolio ARV value — build the companion inline (`'(' + ui.fmtUsd(paise/100) + ')'`) instead of via `fmtDual`. When `fmtUsd` returns the em-dash these render a literal `(—)` rather than dropping the parenthetical, diverging from the `fmtDual` "no rate → ₹ alone" contract. Routing them through a shared helper keeps the fallback uniform.

### Mobile bottom nav: auth-gating and address

`TABS` marks Wallet/Portfolio/History `auth: true`; `tabbarMarkup` filters them out for a signed-out user and substitutes a Sign-in tab, so no account-only destination is exposed pre-auth. The signed-in set gets an Account tab appended only when not already present. The bar is CSS-hidden above 760px. Sign-out is unchanged: the `[data-signout]` handler in `mountNav` still binds and calls `api.logout()`. The support address is exactly `mailto:info@ARVcoin.com` in both the footer column and the nav Help link.

The display gap is the breakpoint mismatch: `.tabbar` shows at ≤760px, but `.nav-links` collapse into the hamburger at ≤880px. Between 761 and 880px the inline links are gone and the bottom bar has not appeared, leaving only the "More" hamburger. Aligning the two media queries closes the band.
